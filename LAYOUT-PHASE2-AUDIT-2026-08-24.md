## Shared structural coverage after Phase 2

All 13 non-legacy calculators now use the shared layer for:

- hero wrapper,
- columns/grid wrapper,
- main content wrapper,
- page-local cards,
- results sidebar.

Across these pages, **67 card wrappers** are now produced through the shared `calculatorCardStart()` / `calculatorCardEnd()` API.

The nine Phase-2 pages no longer contain their old literal structural patterns:

- `<section class="hero">`: 9 → 0
- `<section class="card...">`: 45 → 0
- literal results `<aside>` wrappers: 9 → 0
- `<div class="layout">`: 8 → 0
- `<div class="grid">`: 1 → 0

## Component extension

Phase 2 adds two presentation-only helpers to `calculator-layout.php`:

```php
calculatorHeroStart(...);
calculatorHeroEnd();
```

They allow pages with richer/custom hero internals to retain their exact existing HTML while sharing the structural wrapper. Phase-1 pages that use `calculatorHero(...)` remain fully compatible.

## Rendered-DOM parity

Each Phase-2 page was rendered twice:

1. from the Phase-1 baseline,
2. from the Phase-2 candidate.

The normalized DOM token stream was compared, including:

- element sequence,
- attributes,
- IDs,
- `data-*` contracts,
- text,
- script `src` values,
- inline script text.

**Result: 9/9 exact parity.**

This is particularly important because the migration changes PHP source structure but must not alter the DOM consumed by the existing JavaScript controllers.

## Browser runtime note

A fresh Chromium E2E run is not claimed in Phase 2 because the local Chromium process currently fails to initialize reliably in this container due to DBus/runtime restrictions.

This is mitigated by the stronger relevant migration invariant: the browser-facing rendered DOM **and script contracts are identical before and after** for all nine pages. No business JS changed in the migration.
